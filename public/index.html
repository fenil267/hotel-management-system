Normalized 3NF Schema

Eliminates functional dependencies, transitive dependencies, and data anomalies. Separates guest profiles, room assets, stay bookings, and financial payment transactions into distinct relational entities.

• Rooms: (room_id PK, room_number UNIQUE, price, max_occ, status)
• Guests: (guest_id PK, email UNIQUE, id_proof UNIQUE, phone)
• Bookings: (booking_id PK, guest_id FK, room_id FK, dates)
• Payments: (payment_id PK, booking_id FK, amount, method)

Active SQL Triggers

Automated lifecycle event triggers running directly inside the MySQL storage engine, synchronizing physical room availability in response to booking state changes.

⚡ AFTER INSERT: Auto-sets room to 'Occupied' if walk-in or today's stay.
⚡ AFTER UPDATE: Check-Out → 'Cleaning', Check-In → 'Occupied', Cancel → 'Available'.
⚡ AFTER DELETE: Releases occupied room back to 'Available'.

ACID Concurrency Locks

Overlapping reservation requests execute inside atomic transactions (`beginTransaction()`) using row-level locking (`SELECT ... FOR UPDATE`) to eliminate double-booking race conditions under high concurrency.

✓ Strict Interval Math: (checkin < out AND checkout > in)
✓ Relational deletion cascades & protection rules
✓ CHECK constraints on price, occupants & dates

Relational SQL View Implementation

View definition used for universal fast querying, search, and ledger representation

VIEW: Booking_Details_View 
CREATE OR REPLACE VIEW Booking_Details_View AS
SELECT 
    b.booking_id,
    b.check_in_date,
    b.check_out_date,
    DATEDIFF(b.check_out_date, b.check_in_date) AS total_nights,
    b.num_guests,
    b.total_amount,
    b.booking_status,
    b.booking_date,
    g.guest_id,
    g.full_name AS guest_name,
    g.email AS guest_email,
    g.phone AS guest_phone,
    g.id_proof_number,
    r.room_id,
    r.room_number,
    r.room_type,
    r.max_occupancy,
    r.price_per_night,
    r.status AS current_room_status,
    p.payment_id,
    p.amount_paid,
    p.payment_method,
    p.payment_date
FROM Bookings b
INNER JOIN Guests g ON b.guest_id = g.guest_id
INNER JOIN Rooms r ON b.room_id = r.room_id
LEFT JOIN Payments p ON b.booking_id = p.booking_id;
